Romania - E-invoicing Extension Limits
======================================

Enforces the CIUS-RO maximum field lengths (ANAF SPV schematron rules
**BR-RO-L020 .. BR-RO-L1000**) on the UBL XML generated by
``l10n_ro_edi_extension``, so invoices are not rejected by ANAF for
oversized text.

What this module provides
-------------------------

-  **Field truncation** — party names and addresses, document
   references, payment means, allowance/charge reasons, VAT exemption
   reasons, line item names/descriptions and additional item properties
   are truncated to their CIUS-RO limits. Lengths are counted in Unicode
   characters, matching the XPath ``string-length`` used by the
   validator.
-  **Note splitting** — the invoice note (BT-22) and line notes (BT-127)
   are not truncated but split into repeated ``cbc:Note`` tags of at
   most 300 characters (and 300 UTF-8 bytes) each.

The module is ``auto_install``: it is installed together with
``l10n_ro_edi_extension``.

Use Cases / Context
===================

Key features
============

-  **Automatic CIUS-RO field truncation** — party names, addresses,
   document references, payment means, allowance/charge reasons, VAT
   exemption reasons, and line item names/descriptions are silently
   truncated to their ANAF-mandated limits.
-  **Smart note splitting** — invoice notes (BT-22) and line notes
   (BT-127) are split into multiple ``cbc:Note`` tags of ≤ 300
   characters and ≤ 300 UTF-8 bytes instead of being truncated.
-  **Prevents ANAF SPV rejection** — enforces schematron rules
   BR-RO-L020 through BR-RO-L1000 so e-Factura XML passes ANAF
   validation without manual intervention.
-  **Zero-configuration** — installed automatically alongside
   ``l10n_ro_edi_extension`` (``auto_install``); no setup required.
-  **Unicode-aware length counting** — character lengths are counted as
   Unicode code points, matching the XPath ``string-length`` function
   used by the ANAF validator.
